# 公開版更新の受け入れ条件

記録日: 2026-11-26 JST
根拠: ユーザーの指定「cargoの実行速度が従来より落ちていないこと、rust-analyzerの起動が30s以内で終わることが公開版を更新する条件」。この指定だけで公開更新を実行しない。

## 必須条件

1. Cargo実行速度が従来より低下していないこと。
2. **ページを開いてから、補完・診断が実際に使えるまで30秒以内であること。** ユーザーが明示した起算点・完了点であり、rust-analyzer単体の初期化時間ではない。ページ遷移開始を起点に、ダウンロード・Wasm準備・sysroot/キャッシュ読込・意味解析準備など、利用可能になるまでに発生する待ち時間を含める。補完と診断の両方の実動作を確認する。

両方を測定で確認するまで公開版を更新しない。既存のロック検証CI成功だけでは、この性能条件の合格とはしない。

## 比較の方針（測定前に具体化する事項）

- 公開版のソースコミットは不明。現在配信されている公開版を比較対象として実測する案とし、取得日時・URL・可能なら配信アセットのハッシュを残す。ソースSHAを推測しない。
- 公開版と更新候補を同じマシン・ブラウザ・入力プロジェクト・コマンド・キャッシュ条件で比較する。コールド/ウォーム結果を混ぜない。繰り返し測定し、生ログと失敗も保存する。
- Cargoの対象コマンド、プロジェクト、初回/再実行の扱い、非劣化の判定方法は未確定。未指定の許容低下率を勝手に設けない。
- 30秒の起算点・完了点は上記のとおり確定。ネットワークとキャッシュ条件、対象端末、全試行/分位点等の判定方法は測定前に明記する。平均だけで30秒超過を隠さない。
- 起動/終了メッセージだけでなく、Cargoの期待する実行結果および補完・診断の実動作も確認する。

## 現時点の証拠と未達事項

実験のoff/on比較では、候補の意味解析準備中央値14.90秒、起動全体中央値36.56秒だった。これは公開版との比較ではなく、意味解析準備だけの14.90秒をもって今回の30秒条件を満たしたとはしない。確定したページ開始から利用可能までの条件に対し、当該起動全体の値は30秒を超えるため、この既存結果を合格の根拠にはできない。

Cargoについて公開版との同条件比較による非劣化は、この条件の指定時点では未確認。したがって公開更新条件の合格はまだ宣言できない。

### 2026-11-27 の追加測定

同一Wasm・キャッシュでの初期化改善off/on比較（Chrome150、GitHub hosted runner、A-B-B-A）では、全8訪問で補完候補・型エラー診断の実表示を確認した。ただしページ開始から両チェック完了まで、改善ONは44.97〜54.57秒であり、全訪問30秒超。初回平均は50.79→47.33秒、再読み込み平均は48.42→49.77秒と結果が混在するため、安定した高速化も未確定。別環境・旧Chromeの結果と混ぜない。

[実測報告](<results/startup-proposals-20261126/frontend-45962666995/REPORT.md>)。この比較は公開版との比較ではなくCargo非劣化も含まない。sysroot読取り集約は別のデフォルト無効実験で、ネイティブ・小規模Wasm境界テストが通った段階。アプリ全体の高速化や公開条件達成の証拠にはしない。

### Cargo追加観測（2026-11-28結果回収）

[4条件の観測報告](<results/startup-proposals-20261126/frontend-45965528969/REPORT.md>): 初期化改善OFF/ON/ON/OFFの全4セッションで、実際の初回Cargo実行が180秒以内に期待出力・プロンプト復帰を示さなかった。内部待機状態も全条件で共通。原因未確定で、今回の変更による劣化とは断定できないが、非劣化の合格証拠にもならない。変更なし再実行・編集後再コンパイルには進めていない。180秒はタイムアウト閾値であり実行時間として比較しない。公開更新は引き続き不可。
